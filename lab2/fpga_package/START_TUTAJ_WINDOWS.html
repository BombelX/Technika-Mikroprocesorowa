ZYBO → Vivado → PuTTY

Windows 11 · Vivado 2024.1 · oryginalna ZYBO / XC7Z010

Na start: START_WINDOWS.cmd → klawisz 1.
Na płytce: SW3–SW0 = 0100 → BTN0 → BTN2.

Paczka zawiera źródła i automatyczne tworzenie projektu. Nie zawiera sprawdzonego bitstreamu. Pierwszą budowę musi wykonać Wasze Vivado; testy Windows i płytki pozostają do potwierdzenia.

1. Rozpakuj

ZIP → prawy przycisk → Wyodrębnij wszystkie. Cały katalog umieść w C:\lab2\fpga_package. Nie uruchamiaj z podglądu ZIP.

Potrzebne: pełne Vivado 2024.1 z rodziną Zynq-7000 oraz PuTTY. Samo Vivado Lab Edition nie zbuduje projektu.

2. Podłącz dwa USB i włącz płytkę

  1. Sprawdź, że to oryginalna ZYBO, a nie ZYBO Z7.
  2. Przy wyłączonej płytce sprawdź Pmod USBUART w JE. Jeśli nie jest osadzony, skorzystaj z instrukcji stanowiska i oznaczeń GND/VCC; nie zgaduj orientacji.
  3. Kabel 1: złącze ZYBO PROG/UART → komputer. To programowanie.
  4. Kabel 2: USB małego Pmod na JE → komputer. To dane do PuTTY.
  5. Źródło zasilania JP7 zgodne z użytym zasilaniem; przy USB wybierz USB. Włącz SW4, sprawdź PGOOD.

Zdjęcie do sprawozdania: płytka i oba kable.

3. Otwórz projekt

  1. Zamknij poprzednie Vivado po zapisaniu pracy.
  2. Dwuklik START_WINDOWS.cmd, potem naciśnij 1.
  3. Jeśli pyta o ścieżkę Vivado, wpisz lokalizację bin\vivado.bat z właściwości skrótu Vivado.
  4. Poczekaj na WINDOWS PROJECT READY w Tcl Console. Projekt i pamięć tworzą się automatycznie.
  5. W Project Summary sprawdź xc7z010clg400-1. W Sources top to toplevel; pamięć nie może mieć znaku zapytania.

Przy kolejnych uruchomieniach otworzy ten sam projekt. Można też otworzyć build\load_store_lab2\scs.xpr przez File → Project → Open. Zachowaj cały folder paczki.

4. Zbuduj i wgraj

  1. Generate Bitstream → Save / Yes / OK, jeśli pyta.
  2. Poczekaj na Bitstream Generation Completed.
  3. Open Implemented Design → Reports → Timing → Report Timing Summary. Sprawdź spełnienie setup/hold i istotne nieograniczone ścieżki; błędy pokaż prowadzącemu przed wgraniem.
  4. Open Hardware Manager → Open Target → Auto Connect.
  5. Program Device → xc7z010_1.
  6. Bitstream file: build\load_store_lab2\scs.runs\impl_1\toplevel.bit → Program.

Powinna świecić DONE. Screeny: timing, hierarchia i Hardware Manager.

5. Znajdź COM Pmod i otwórz PuTTY

  1. Start Windows → prawy przycisk → Menedżer urządzeń → Porty (COM i LPT).
  2. Odłącz tylko kabel 2: port, który zniknął, to Pmod. Podłącz go ponownie i odczytaj COM.
  3. PuTTY → Serial, Serial line: Wasz COM, Speed: 115200.
  4. Connection → Serial: 8 / 1 / Parity None / Flow control None.
  5. Session → Logging → All session output, wybierz plik. Wróć do Session → Open.

Na kolejne uruchomienia można użyć PUTTY_WINDOWS.cmd: wpisz COM, skrypt ustawi transmisję. Logowanie włącz ręcznie. Nie wpisuj loginu ani komend do terminala; to wyjście debuggera.

6. Ustaw dokładnie 0100 i naciśnij przyciski

Sprawdź nadruki numerów przełączników. Kolejność zapisu to SW3, SW2, SW1, SW0.

SW3SW2SW1SW0
0 / dół1 / góra0 / dół0 / dół
  1. BTN0 naciśnij i zwolnij — reset. Poczekaj sekundę.
  2. BTN2 naciśnij na około 0,1 s i zwolnij. Poczekaj sekundę.
  3. PuTTY: cztery wiersze c=1, c=2, c=3, c=0. To jedna instrukcja.
  4. Powtarzaj BTN2. Do tabeli sprawozdania bierz ostatni wiersz c=0.
Naciśnięcie BTN2 od resetuOczekiwany wynik
4R0=6, R1=0
5R0=6, R1=5
6R0=B, R1=5 — wynik 6+5=11
7Przedostatni bajt M: to 0B; końcówka: … 05 0B 00
8PC=0 — początek następnej pętli

Screeny po naciśnięciach 6 i 7. Puste PuTTY przed BTN2 jest normalne.

7. Pozostałe ustawienia i testy

SW3–SW0Działanie
0100BTN2: instrukcja i 4 wiersze. Ustawienie startowe.
0101BTN2: jeden takt i 1 wiersz. Cztery naciśnięcia na instrukcję.
0000BTN2: instrukcja; po sekundzie BTN1: jeden zrzut.
0110Sam wykonuje i wypisuje jeden takt/s.
1010Sam wykonuje takty, ale bez automatycznych zrzutów.

Zmiana trybu → BTN0 przed ponownym liczeniem kroków. Reset nie przywraca RAM. Po wyłączeniu zasilania ponów Program Device.

Do dalszych testów: zamknij Vivado, uruchom START_WINDOWS.cmd i wybierz: 2: MUL zgodne z Pythonem, 3: SUB, 4: ADD do R1, 5: MUL lab2, 6: program bazowy. Każdy nowy projekt wymaga budowy i wgrania. Opcje 1 i 4 pokazują wybór rejestru ADD.
